Foreground service use

Package com.nomnomsom.armstrongandgetty · declared type mediaPlayback

Summary. The app is an audio podcast player. It uses a mediaPlayback foreground service for one thing only: to keep the episode the user started playing audible after they leave the app or lock the screen, with an ongoing media notification that shows what is playing and lets them control it.

Video demonstration

The recording below shows the full flow: starting an episode, leaving the app, background playback continuing with the media notification, controlling playback from that notification, and returning to the app with playback uninterrupted.

Direct link to the video file (MP4)

Declared permissions

  • android.permission.FOREGROUND_SERVICE
  • android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK

The service is declared in the manifest as android:foregroundServiceType="mediaPlayback" and is implemented with Jetpack Media3 (MediaLibraryService), which posts the standard system media notification.

When the service starts and stops

  • Starts only when the user presses play on an episode.
  • Runs only while audio is playing or paused mid-episode, so the user keeps a lock-screen and notification control they can return to.
  • Stops when playback finishes, when the user stops playback, or when the user dismisses the media notification.

The service is never started from the background, never started at boot, and does no work unrelated to playing the audio the user asked for.

Why a foreground service is required

Continuing audio after the user leaves the app is the core, user-visible purpose of a podcast player, and it is the use case Android documents for the mediaPlayback service type. Without it, playback would be killed as soon as the app was backgrounded or the screen locked, and the media notification and lock-screen controls would disappear.
